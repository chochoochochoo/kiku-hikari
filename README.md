# kiku-hikari（聴く・光）— 曲を聴いて、ムービングライトが光る

このプロジェクトは、照明オペレーターを置けない小さな会場で照明が拍に合わせて点滅するだけになる問題を解くライブ照明エージェントです。照明家の判断を、次の人に受け継ぐ形として日本語の知識ファイルにまとめました。各規則に出典を付けています。Claude が曲を聴きながらこの知識ファイルを使い、曲の展開に合わせた照明に変えます。

Built with Claude: Japan 2026 の提出作品。主催は Cerebral Valley × Anthropic、期間は 2026-11-02 12:30 〜 11-08 20:00。制作: I LLC。
このリポジトリの内容はすべてハッカソン期間中に Claude Code で新規に制作した。期間前の準備は下の「11/2 前に行った準備」の節に書く。
2026-11-04 に履歴を書き換えたため、それより前のコミット ID は無効。リポジトリ: https://github.com/chochoochochoo/kiku-hikari
デモ動画は完成版 v5、2 分 57 秒、限定公開、11/8 公開: https://youtu.be/FdzBavUcjDU
ナレーションは VOICEVOX:冥鳴ひまり。第 2 段の判定の結果カード入り。初回提出に添えたドラフトと本編 v1 はこの版に差し替えた。

> 「聴く」と「光」は、ふだん一緒に使われない言葉です。小さな会場では、照明は拍で点滅するだけになりがちです。
> このソフトは、演奏中の曲を聴いて曲の構造を先読みし、サビの頭でちょうど開く・静かな場面は青く沈める、といった照明オペレーターの判断を Claude に肩代わりさせます。

- **当事者か**: 作者は公共ホールの舞台設備を本業で設計している。音響・映像・照明の設備で、照明オペレーターを置けない現場を設計の側から見てきた。
- **日本特有か**: 公民館・学校の体育館・地域のホールでは、照明の設備はあっても操作する人がいない例を、作者は設計の仕事で多く見てきた。これは統計ではなく作者の経験である。知識ファイルは日本語で、J-POP・アイドル・ミクスチャー・演歌の公式ライブ映像の観察から作った。
- **期間後も使われるか**: Windows の PC 1 台と市販の Art-Net ノードで動く。Art-Net は TCP/IP 上の照明プロトコル。灯体が無くても `--viz` で画面で確かめられる。知識ファイルは `tools/import_knowledge.py` で差し替えられるので、会場や照明家が自分の規則を足して使い続けられる。ライセンスは `LICENSE`。

用語の注: 本書とログの「開く」は、境界で明るさと色を切り替えること。動画では現場のキュー出しの合図「GO」と呼んでいる。

## 審査員の方へ: 5 分で手元で動かす — 公開 URL・ログインは無し
このソフトはマイクと LAN の灯体を動かす PC 用のプログラムなので、ブラウザで開く URL はありません。灯体もマイクも無くても、WAV 1 本で画面の仮想灯体が動きます。これを疑似モードと呼びます。追加のログイン情報はありません。
```bash
git clone https://github.com/chochoochochoo/kiku-hikari && cd kiku-hikari
py -3.12 -m pip install numpy sounddevice soundfile pydantic anthropic   # Windows・Python 3.12 で確認。画面は tkinter で、Python に同梱
copy .env.example .env         # ANTHROPIC_API_KEY= に自分の鍵を入れる。.env は .gitignore 済み
py -3.12 -m kiku_hikari.main --mode claude --file song.wav --viz --no-artnet --fixtures 3 --pars 8 --spots 6 --seconds 90
```
- `song.wav` は手持ちの曲を 48 kHz の WAV にしたもの。他の形式は `ffmpeg -i in.mp3 -ar 48000 song.wav` で変換します。サビのはっきりした J-POP が向きます。曲はリポジトリに入れていません
- 画面: ムービングライト 3 台を色つきの丸で描きます。丸の位置が Pan/Tilt、丸の大きさと濃さが明るさ、黒はシャッター閉です。下に拍・テンポ・Claude の最新の判断が 4 秒ごとに出ます。判断は区間・色・情景一語・理由です。Par 8 台とスポット 6 台は画面には描かず、値は走行ログ `logs/` の `dmx` 行に残ります。サビの頭で開き、静かな場面は青く沈みます
- 鍵が無い場合: 拍連動のみの `--mode beat` か、Claude を使わないルール表の `--mode rules` で同じ画面が動きます。灯体がある場合の配線は下の「セットアップ」の節
- 審査で見比べる用に、動画と同じ走行のログを `logs/public/` に置いています。説明は「第三者のブラインド判定」の節

### 補足: 動画と同じ 3D の画面で見る — kuwatec PrefLight
動画の灯体の絵は、kuwatec の照明ビジュアライザ PrefLight の表示を録画したものです。既製のソフトで審査の対象外ですが、同じ絵を手元で出せます。
公式ページ: http://www.kuwatec.co.jp/preflight/jp/
- 公式ページの記載: Windows 64bit・32bit と macOS 版をダウンロードできる。Art-Net・OSC で制御できる。製品パッケージは 31,240 円で、ユーザー登録が完了するまでの試用の制限は「ファイルへの保存ができない」「動画への記録が最長 10 秒」「起動時とファイル読み込み時に未登録のメッセージが出る」の 3 点。11/8 に公式ページとオンラインマニュアルで確認しました
- 手順: PrefLight を起動し、このリポジトリの `preflight/stage.plt` を開く。灯体 23 台と演者 3 体が入っていて、アドレスはこのコードの既定値どおりです。ムービング 3 台が 1・12・23 の 11ch、Par 14 台が 34 から 9ch ずつ、スポット 6 台が 501 から 1ch ずつ、Art-Net はユニバース 0
- 送り方: 上の起動コマンドの `--viz --no-artnet` を `--node <この PC の LAN アドレス> --universe 0 --fixtures 3 --pars 14 --spots 6 --profile show` に替える。送り先を直接指定すると ArtPoll の探索はしません。PrefLight が UDP 6454 を使うので、同じ PC の他の Art-Net 送信は止めます。この PC では 127.0.0.1 宛が届かない時があり、LAN アドレス宛で安定しました。詳細は `docs/hardware-notes.md` の PrefLight の節
- 動画の撮影に使った起動は、この送り方に `--seconds` を足しただけです

## 誰のためか
公民館・学校・小さなライブハウスなど、照明オペレーターがいない小規模の現場。作者は音響・映像・照明の舞台設備を設計する側の人間で、「拍で点滅するだけ」の現状を何年も見てきました。

## Claude の役割 — 製品の中
Claude API の `claude-opus-5-5` が約 4 秒ごとに、直近 30 秒の音の要約＝音量・明るさ・オンセット密度・テンポ・これまでの区間を受け取り、Enum 固定の JSON で返します。実装は `kiku_hikari/claude_worker.py`。返す項目:
次の境界まで何小節。既定で、小節頭で開く／いまの区間と次の区間／開き方＝hard_cut・ramp・bloom・blackout_then_burst／色と次の色／動きの語彙＝hold・sweep・chase・bounce／溜め＝dim_hold・slow_close・freeze／感情 2 軸＝快不快・覚醒度／浮かぶ情景を一語／確信度／理由。
拍・位相・数値・安全は Python が担当し、Claude は秒単位の判断だけをします。Claude が流れを止めない設計です。

## 他モデルは監査と知識の材料集めにだけ使用
製品コードを書いたのは Claude Code だけです。OpenAI Codex と Gemini は「漏えい防止の仕組みの監査」に、Gemini は知識ファイル v2 の材料集めにも使いました。材料集めでは公式ライブ映像の照明の変化を時刻つきで書き出させ、渡したのは URL だけで、動画はダウンロードしていません。ローカル LLM は期間前の話題出しに使いました。照明の判断をするのは製品の中の Claude だけです。何にどう使ったかは `docs/ai-usage-log.md` に時刻つきで残しています。

## Claude Code で何を作ったか — この節が最長
- **2 つの輪**: 速い輪は Python・40 Hz・`main.py`、遅い輪は Claude・約 4 秒・`claude_worker.py`。遅い輪は別スレッド・同時 1 件・世代番号つきで、古い返答は捨てる。失敗やレート制限は「返答なし」として速い輪を止めない
- **自前の拍追従** `beat.py`: Windows の Python 3.12 に aubio・madmom が入らないため、対数スペクトルのフラックス→自己相関＋倍音加算→櫛で位相合わせ、を numpy だけで書いた。評価は `tools/beat_eval.py` で、結果は `docs/eval-beat.md`。生成時に指定した BPM は当てにならないと判明した
- **先読みエンジン** `engine.py`: Claude の予測境界を「直後の小節頭」にクオンタイズして開く。溜めは境界の 1 小節前から。予測が外れても音響変化検出の `change.py`、CUSUM が後から境界を見つけて開く。これを救済と呼ぶ。位相リセットはしない
- **灯体と安全** `fixtures.py`: ADJ Stinger Spot 11ch の表。取説の画像ページを Claude Code が読んで転記した。Pan/Tilt のスルーレート制限、ストロボ上限、明るさ上限
- **Art-Net** `artnet.py`: ArtPoll で EtherMX を探し、ArtDmx をユニキャスト。標準ライブラリのみ
- **ログ** `runlog.py`: 拍・テンポ・位相・Claude の要求/応答・DMX・遅れを 1 本の JSONL に時刻つきで。動画の字幕とブラインド判定の照合はここから作る
- **知識ファイル** `knowledge/lighting_knowledge_v2.json`・既定: 「区間×感情×色・動き・溜め」の規則 34 本。照明の現場の規則を Claude が研究の原文と公式ライブ映像の観察から起こし、作者が採否と優先順位を決めた。11/7 に、作者が本文を決めて採用した 2 本と、現場の照明家の指摘から起こして作者が採否した 3 本を足した v3 を `knowledge/lighting_knowledge_v3.json` に用意した。37 本。測定は v2 で行い、既定は v2 のまま。v3 は `--knowledge knowledge/lighting_knowledge_v3.json` で使う。v1 は `lighting_knowledge.json` の 25 本で、研究の原文から Claude Code のサブエージェントが下書きした。原文は Palmer 2013 の音楽→色、先読みフェードの特許、点滅の安全基準。v2 では、公式ライブ映像 110 本を Gemini に時刻つきで書き出させ、それを Claude が集計して規則を差し替えた。110 本のうち 10 本は電子ロックの別枠で、そのジャンルの時だけ効く規則 4 本になった。例: サビは白が主役、1 曲に 4 色、pre_chorus はサビの約 16 秒前に色を変える、ブレイクで暗転するのは 3 割だけ、演歌はサビで白を足さず 2 色で幕と背景で山を作る。各規則の出典は時刻つきの動画の URL。差し替えは `tools/import_knowledge.py` で上書きするだけ。system の固定部に置いてプロンプトキャッシュに乗せる。実測では毎回約 19,600 トークンがキャッシュ読みになる
- **疑似モード** `--file` と `--viz`: 灯体もマイクも無い人が WAV を入れて画面の仮想灯体で見られる
- **公開リポジトリの守り** `tools/secret_scan.py`・`.claude/settings.json`・GitHub Actions: Claude Code の PreToolUse フック／git の pre-commit・pre-push／CI の 3 層で鍵・個人情報を止める。敵対レビュア 2 体・Codex・Gemini の監査で見つかった抜け道 30 件超を反映し、`tools/test_secret_scan.py` の一時クローンでの 39 ケースで機械確認
- **評価を先に** `docs/eval-blind.md`: 第三者 3 人のブラインド判定。同じ曲で ① 拍連動／② ルール表／③ Claude を A/B/C に匿名化

## いま動くもの
```
py -3.12 -m kiku_hikari.main --mode claude --file song.wav --viz --no-artnet   # 灯体なし: WAV→画面の仮想灯体
py -3.12 -m kiku_hikari.main --mode claude --seconds 90                         # 灯体あり: マイク→Art-Net
py -3.12 -m kiku_hikari.main --mode beat   --seconds 60                         # ① 拍連動のみ。--bpm 120 で固定テンポ、Space で拍頭合わせ
py -3.12 -m kiku_hikari.main --mode rules  --seconds 60                         # ② ルール表・Claude なし
py -3.12 -m kiku_hikari.main --mode claude --play song.wav                      # 自己試験: ヘッドホン→マイクで聴かせる
py -3.12 -m kiku_hikari.artnet                                                  # Art-Net ノードを探す
```

## セットアップ — 審査員の方へ
